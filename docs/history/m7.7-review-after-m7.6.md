# M7.7 — Review after M7.6

A stop before the real install's check, asked for by the user: a security and code quality
review of the whole code (bugs too, where one shows), the first since
[M5.6](m5.6-review-after-m5.5.md), over everything M5.7 to M7.6 added (about 84,000 lines of
sources, with their tests, the tooling and the docs): the wiping allocator, the skill,
amendments and renewals, workspaces, per-repository tickets, the CLI's admin commands, local
mode on both systems, upstream proxies, the Secure Enclave signer and hardware-wrapped
secrets. Then every finding fixed with the test that would have caught it, or moved to the
milestone that owns it. The real install's check, numbered M7.7 until this review took the
number, is [M7.9](m7.9-local-mode-checked-on-the-mac.md).

**Status:** done (2026-11-13). `make ci` and `make e2e` passed on the closing tree (the
numbers are under [the closing runs](#the-closing-runs)): every finding fixed with its test or
moved with its line in a later milestone, the failures the first runs found fixed.

- **The review**: thirteen reviewers in parallel, one per area, each named by the letter of
  its findings: `C` the policy core, `P` configuration, protocol and store, `A` the approval
  service, `G` the gateway and `writ-git`, `M` the mirrors, `K` crypto, the signer and the
  allocator, `S` the keystore, `D` the daemon, `L` local mode and the installers, `U` the
  approver's CLI, `W` the agent's CLI and `writ-sign`, `T` the tests, `X` tooling and docs.
  Each finding was checked against the code, then against the later milestones, the
  [threat model](../threat-model.md)'s residual risks, [security.md](../security.md)'s known
  gaps and the [open questions](../decisions.md#open-questions), before it was kept. Two
  highs, twenty-six mediums, the rest low; a finding two reviewers made is merged and fixed
  once.
- **The report was discussed with the user**, who decided what is fixed here, what moves and
  what is accepted (the [decision log](../decisions.md)'s M7.7 rows):
  - **Scope:** every finding fixed or addressed here, unless a later milestone owns it; that
    one gets a line in the milestone's section.
  - **H1 (`S-1`):** the authority MAC is verified inside the unseal, right after the authority
    key opens, before anything is written or reconciled; `unseal: auto` read at a sealed start
    is untrusted until then.
  - **H2 (`L-1`):** the approval client checks every signed document it builds (admin, token,
    unseal, scan, TLS and CA rotation): the daemon a reply names must be the fingerprint of the
    host key or TLS certificate the client authenticated, and a text shown must match its
    digest. No root-owned pins. No separate admin key now: an open question on
    [M11's page](../backlog/multi-user.md#open-questions).
  - **The session root (`C-1`, `L-3`):** a binding's root must be the direct child of a `writ`
    the daemon recognises by its kernel-attested executable path, the installed one
    (`session_launcher` in `writd.yaml`, its default beside `writd`, checked at start).
  - **Expected paths (`U-1`)** are never elided by `writ sign`; agent prose stays cut at 40
    rows.
  - **Recipients (`S-8`):** removing or replacing a keystore recipient rotates the data key,
    crash-safe (a rotation cut short is finished or undone at the next unseal).
  - **Residual risks:** one new row (local mode's agents share the approver's OS user) and
    three sentences corrected; no row for the install tree (`L-2`), a token printed back by a
    remote (`M-1`) or the TLS key on a device (`K-3`, one sentence in the row on listeners
    without `allow`).
  - **Operator pages (`X-4`):** `make check` refuses an operator page holding an `sh` block
    the pipeline's table doesn't list.
  - **Small forks, the defaults taken:** `writ init --whole-repo` refuses a linked worktree
    (`W-1`); `writ init` refuses an `origin` with a `pushurl` or several URLs (`W-3`); the e2e
    images' apt packages pinned to a Debian snapshot date; the token replay (`A-6`) confirmed
    first, then a count of changes in the document (`writ-token/3`).

## The closing runs

The steps ran `make ci` only at the milestone's end, by the user's choice: each step ran
clippy, the check scripts, the tests of the crates it touched and the related integration
tests. The closing step ran both pipelines for the first time since step 3.

- **`make ci`** passed at once on the closing tree (1,146 tests passed, 42 skipped: the
  end-to-end scenarios and the gates for the other system), then again after the fixes below
  (1,147 passed, 42 skipped).
- **`make e2e`**: the images built for the first time with their apt packages from the
  Debian snapshot (reached, no fallback), and the Linux session watcher's change compiled
  there. The first run: 32 scenarios passed, 6 failed, each a scenario written against the
  code before a step, or a bug the steps' unit tests couldn't see:
  - **The run under `writ run` (`local_mode`, scenario 24)**: its clone kept the token in
    `origin`'s URL, which `writ init` refuses since `W-8`, so the harness stopped at `writ
    init` and the session ended with the lease. The clone now keeps it in a credential helper
    of its own, as every other scenario's.
  - **`whole_repo` and `wrapper_mode`** looked for the old `origin` URL holding the token; they
    now check the plain one (and `whole_repo` the `pushInsteadOf` beside `insteadOf`, `W-3`).
  - **`sessions_and_renewals`** checked that `WRIT_RUN_PID` is the harness's parent; since
    `C-1` the harness is the session's root, so it is the harness's own pid (`$$`).
  - **`upstream_proxies`, a direct upstream that can't be reached**: a bug of `M-6`. Every
    `ssh://` operation now goes through the daemon's byte-capping tunnel, so git only says
    that tunnel failed, and a failure to reach upstream directly lost its reason (and
    upstream's name) from the audit line. The error now carries the dial's reason with
    upstream named, directly as through a proxy; the agent is still told only that upstream
    can't be reached (`a_direct_upstream_that_can_t_be_reached_is_named_in_the_error_never_to_the_agent`,
    failing on the code before; [gateway.md](../architecture/gateway.md)).
  - **`upstream_proxies`, the repos reached through the proxies**: failed only because the
    scenario above stopped half way, with the shared repository left direct (it runs alone,
    `Stack::exclusive`, and puts the policy back only at its end). Run again after the fix,
    it passed; not a test that fails under load.
- **The second `make e2e`**, after the fixes and the second `make ci`: every scenario passed
  (38 passed, 0 failed, in 234 s).
