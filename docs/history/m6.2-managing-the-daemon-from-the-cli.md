# M6.2 — Managing the daemon from the CLI

Every key declared in the signed policy, the upstream host keys pinned by signed changes,
repos naming their templates, and `writ admin repo|template|key|host` to read the policy in
force, add to it step by step and change it one field at a time, from the approver's machine
with no host access ([the design page](../backlog/daemon-management-from-the-cli.md),
[approvals](../architecture/approvals.md#reading-the-policy-entry-by-entry), the operator
[setup](../operators/setup.md)). The design settled with the user (the decision log's
2026-11-04 and 2026-11-05 M6.2 rows).

**Status:** done (2026-11-05). `make ci` passes; `make e2e` passes (32 scenarios). All run
on macOS; CI runs the same on Linux.

## What was planned

[The backlog page](../backlog/daemon-management-from-the-cli.md) holds the design and the plan.
Today keys are declared in two files (signing keys) or not at all (upstream credentials),
upstream host keys are a host file, templates list their repos, and the public keys come only
from host commands: setting up a repo means host access, a restart and a new unseal, which in
local mode (M7) goes through `sudo -u _writd`. After M6.2 the operator does it all from
`writ`, with one signature per change.

- **Every key declared in the signed policy** (`keys:`, signing keys and upstream credentials
  with their use, kind, algorithm, hash, backend, and the OpenPGP user ids), made by the
  change that declares it; `writd.yaml` keeps only the host's settings; `writd keys create`
  goes.
- **Upstream host keys in the policy** (`upstream_hosts`), pinned by a signed change after a
  scan the daemon makes on an approver's signature and the operator compares;
  `mirrors.known_hosts` goes.
- **Repos name their templates** (`repos.<name>.templates`, `[]` pauses a repo); templates
  no longer list repos.
- **No move from the old shape** (Writ isn't deployed): the old fields refused wherever they
  appear, each naming its new place; the state version moves to 10.
- **`writ admin repo|template|key|host`**: `list`, `show` (`key show --public`), `add` and
  `edit` step by step, `set <name> <field>=<value>…` for one field at a time (`+=`, `-=`, `!`),
  `remove` (`--yes` without a terminal; a removed key deleted after its id is typed again),
  `key rotate`, `host rescan` (a pinned host scanned again when its keys changed), `repo check`
  (read and write access proven with nothing pushed). Each
  command one signed change, shown as a diff.

## What was done

Seven commits on main, one per step of the plan:

1. **The policy's new shape** (`writ-core`): `keys.<id>` (use, kind, format, algorithm, hash,
   uids, host, backend), `upstream_hosts`, `repos.<name>.templates`; the canonical writer
   (`PolicyConfig::to_yaml`, Writ's layout); the old fields refused naming their new place;
   state version 10.
2. **The daemon on the new shape** (`writd`): keys checked against their backend wherever a
   policy is read (`declared.rs`), every declared key made by the change that declares it,
   a key no longer declared deleted once the change applies (`Signer::remove_key`, a
   leftover swept at unseal); host pins from the signed policy; `writd keys create` and
   `writd.yaml`'s `signing_keys` and `mirrors.known_hosts` gone (refused).
3. **The reads**: `writ admin repo|template|key|host list` and `show` with the reader key,
   `key show --public` (each key's public half from its signer, an OpenPGP certificate, a
   token only as added).
4. **Field edits**: `set <name> <field>=<value>…` (`=`, `+=`, `-=`, `!`, `field=`), `remove`
   (refused while something uses it, a key's id typed again), one signed change shown as a
   diff, refused when the policy changed in between (`writ_core::config::edit`).
5. **The guided flows**: `add` and `edit` step by step on a terminal (only the fields an
   entry needs, its bounds and default), `template add --from`, a repo's new credential
   declared in the same change, `key rotate`.
6. **The daemon's checks**: the host key scan on an approver's signed `writ-scan/1` and a
   one-use nonce (russh in `writ-mirror`, Ed25519, P-256, P-384, `mirrors.scan_timeout`),
   pinned only by a second signed change; `host rescan` (added at the user's request) for a
   host whose keys changed; `repo check` (read, sync, a dry-run push that sends nothing); a
   guided `repo add` scanning a host with no pin and checking the repo once its key is
   registered.
7. **Docs and the pipeline**: the operator setup rewritten around `writ admin` (`writd init`
   on a policy that can start with no entry, then hosts, templates, keys and repos from the
   approver's machine), run by the pipeline exactly as written (`writ-e2e/src/setup.rs`
   adds a repo on a new host with a new template and key, then checks it); the daily
   operations page's policy changes entry by entry; the remaining registry rows.

## The security checklist, for M6.2

1. **Inputs:** the policy's new sections (`keys`, `upstream_hosts`), bounded and checked
   field by field; `field=value` arguments; the `writ-scan/1` document; what a scanned host
   sends; what upstream says on a check: each in the inventory with its hostile test.
2. **Authority:** keys and host pins change only by a signed policy change; a scan only on
   an approver's signature over this daemon and a fresh nonce (a reader key alone can't make
   the daemon reach a host); a check only of a repo the policy names.
3. **Fail closed:** the old shape refused everywhere (start, admin change, `writd init`,
   `writd recover`), never converted; a declaration the backend can't do stops the change or
   the start; a change made in between refuses an edit; a scan or check that fails pins or
   changes nothing.
4. **Audit:** a removed key's public half in the `admin` line, each key swept at unseal one
   line; `scan` and `check` lines, allowed and denied.
5. **Revocation:** a removed signing key is out of its signer at once; a tightened or closed
   template denies its leases.
6. **Secrets:** a removed key deleted whole and wiped; reads show public halves only, a
   token only as added.
7. **Display:** every daemon and policy text shown escaped; hostile host keys and upstream
   messages tested.
8. **Dependencies:** russh in `writ-mirror` (already in the tree); rustix's `pty` in
   `writ-integration` (tests only).
9. **Guarantees:** two new rows (keys and pins only by signed change, a removed key deleted
   for good; a host reached only on an approver's signature), with their tests.
10. **Threat model:** boundary 5b (the files that grant authority) and 7 (the outbound
    operations, the scan only as good as the network, hence the comparison); the residual
    risk of a mistaken key removal, accepted with the user.
