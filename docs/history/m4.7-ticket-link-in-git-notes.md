# M4.7 — Ticket link in git notes

`ticket_link: notes` ([Q25](../decisions.md)): projects whose commit conventions don't allow a
`Writ:` trailer still get each commit's lease on the remote, readable without asking the
daemon: a git note, `Writ: <lease id>`, which annotates a commit without changing it (same
hash, same signature). The daemon writes it from its ledger once upstream took a push, and
pushes it after the branch ([gateway § Notes](../architecture/gateway.md#notes)).

Decided before building, with the user:

- **`proxy` writes notes too** (M9): the notes job never needs the annotated commits, only a
  repository holding the notes ref, so `proxy` gets a notes-only one per repo.
- **The notes job keeps the mirror's notes ref in step**, not the sync: git refuses a fetch
  naming a ref upstream doesn't have yet, even from a configured refspec (tried), so a sync
  fetching it would fail on every repo without notes.
- **Notes commits are unsigned**, by `writd <writd@writ.invalid>`: no remote verifies or shows
  a notes commit's signature, and the ledger, not the note, is the reference. A daemon key of
  its own for notes adds no security where the remote can't limit a key to `refs/notes/*`
  (GitHub, Codeberg, Forgejo, Gitea); it went to the
  [multi-user backlog page](../backlog/multi-user.md) (now M11), where it gives the shared ref
  one owner.
- **The notes push takes its credential as a parameter**, recorded with each waiting note:
  the repo's `upstream_credential` today; M11 decides which credential pushes a batch.
- **The ref is a per-repo choice, `refs/notes/commits` by default** (`notes_ref: commits` or
  `writ`, only with `ticket_link: notes`): found while writing the end-to-end scenario,
  Forgejo 13.0.5 shows notes on a commit's page and in its notes API from `refs/notes/commits`
  only (checked on the pinned image; Gitea's code is the same, GitHub shows none), and
  `git log` shows that ref without `--notes`. The user chose the setting, with git's ref as
  the default.

## What was done

- **`writ-store`**: schema 5, each ledger entry's `note` (none, `pending`, `written`) and
  `note_credential`; `notes_add_pending` (only the ledger's entries for that lease and repo, a
  written note stays written), `notes_pending` (oldest first, bounded), `notes_written`, each
  in one transaction; a pending note without its credential is refused as corrupt. The audit
  log's `notes` event and `count` field; `key` names the credential on a `notes` line.
- **`writ-core`**: `ticket_link: notes` taken (no longer refused at load); `notes_ref`
  (`NotesRef`), refused without `notes`.
- **`writ-approval`** (`service/notes.rs`): `notes_to_write` (after an upstream push: the
  commits wait, with the repo's credential, when the repo asks for notes), `pending_notes`,
  `notes_pushed` (marked written, one allowed `notes` line per lease and credential: `count`,
  `key`, `refs`), `notes_refused` (one denied line per lease, with the reason; the notes stay
  waiting), `notes_ref`.
- **`writ-mirror`** (`mirror/notes.rs`): `MirrorGuard::push_notes`: the credential must be the
  repo's; a batch of 1 to 10,000 notes, each 1 byte to 64 KiB, one per commit, checked before
  any git runs; the batch as a commit of its own (a blob per distinct text, `mktree`,
  `commit-tree` with no parent), merged into the mirror's notes ref
  (`git notes merge -s cat_sort_uniq`), pushed without force; refused as behind it
  (`fetch first`, `non-fast-forward` on that ref, from git's porcelain output), that one ref
  fetched forced (a sync's checks and bounds, its partial pack removed when it fails), merged
  again, pushed once more; a second refusal, or any other, is an error with upstream's words.
  One operation's access (an agent socket or a credential socket and proxy) for the whole
  push; `mirrors.timeout` for what reaches upstream, `LOCAL_WORK_DEADLINE` for the local work.
  The HTTPS reach carries its credential id.
- **`writ-gateway`**: after an accepted push upstream, `notes::after_push` (off the hook's
  path) records the waiting notes and starts the repo's notes job, which takes the mirror lock
  (so it runs once the push's `receive-pack` gave the mirror back), reads the waiting notes,
  and pushes them one batch per credential, a `Writ:` line per lease each commit waits under.
- **Docs**: the gateway's Notes section, flows § 3 and 3b, the lease model's rule, the operator
  reference (`ticket_link`, `notes_ref`), template and setup guide (reading the notes, the
  credential's permission), the audit fields and ledger schema, the input inventory, the
  threat model, AGENTS.md's naming table, three decisions.

## Findings

- **A failed notes fetch left its partial pack in the mirror** (`tmp_pack_*`): found by the
  hostile-input test (a malformed commit as upstream's notes ref); removed like a failed sync's.
- **Forgejo shows only `refs/notes/commits`** (above): the roadmap's "shown by Forgejo and
  Gitea on the commit page" held only for git's own ref.
- **The CI on Linux had been failing since M4.5**: `a_request_longer_than_the_bound_is_refused`
  read a reset as an error (Linux resets a socket closed with unread bytes, macOS doesn't);
  fixed before this milestone (`3d739f9`).
- **Notes show in `git log` with a 4-space indent under `Notes:`**, and `git notes show`
  prints a note as stored (no newline added): what the tests compare.

## The security checklist, for M4.7

1. **Inputs**: one new, upstream's notes ref and what upstream says of a notes push, in the
   [inventory](../security.md#untrusted-inputs): fetched only when the daemon's push is
   behind it, with a sync's checks and bounds
   (`a_malformed_notes_ref_upstream_never_lands_and_the_notes_push_fails`); git's porcelain
   read only for that ref's `fetch first` or `non-fast-forward`
   (`only_a_notes_ref_upstream_moved_is_behind`). The batch the gateway builds is bounded in
   count and bytes, checked before any git runs
   (`a_batch_with_the_wrong_credential_or_malformed_is_refused_before_any_git`).
2. **Authority**: nothing new grants or reads. Notes are written from the ledger, never from
   what an agent says; an agent still pushes branches only (`an_agent_pushing_a_notes_ref_is_refused`,
   and end to end). The upstream credential pushes one more ref, the operator's choice.
3. **Fail closed**: a credential that isn't the repo's, a malformed batch, a refused or
   unreachable remote, a second refusal: no notes pushed, a denied line, the notes waiting; the
   branch push stands. `notes_ref` without `notes` is refused at load.
4. **Audit**: every notes push writes one line per lease, allowed or denied with the reason;
   a failure to record the waiting notes writes a denied line too.
5. **Revocation**: nothing holds a decision; a lease's notes are pushed after its push even if
   it is revoked meanwhile (the commits are already upstream).
6. **Secrets**: unchanged: the notes push reaches upstream through the same one-operation
   access as a sync; upstream's words cleaned, the HTTPS token taken out.
7. **What people see**: the agent sees nothing new; refusals reach the audit log only, cut and
   cleaned.
8. **Dependencies**: none.
9. **Guarantees**: "pushes only to allowed repos and refs" gains
   `an_agent_pushing_a_notes_ref_is_refused`.
10. **Threat model**: boundary 7 names the notes ref; "not guaranteed": that a note on the
    remote is the daemon's (unsigned, writable by anyone with push access); one residual
    risk: a push's notes lost if the daemon stops between upstream taking the push and the
    commits recorded as waiting (the ledger keeps the link).

## Acceptance

- [x] A repo with `ticket_link: notes` takes commits without a trailer; after a push, the
      remote has a note for each pushed commit naming its lease, and every commit's hash and
      signature are unchanged.
  *Integration (`tests/notes.rs`, real git, ssh and the daemon's gateway):
  `a_push_leaves_a_note_per_commit_upstream_the_commits_untouched` (no trailer, the note of
  each commit upstream, the commit objects byte for byte with their signatures, the audit
  line, the mirror's notes ref, `git log` showing it), `notes_go_under_refs_notes_writ_when_the_repo_says_so`,
  `a_repo_without_notes_gets_none`, `notes_reach_an_https_upstream_with_its_token`; end to
  end, scenario 14.*
- [x] Two leases pushing to one repo at once both get their notes; none is lost.
  *`leases_pushing_to_one_repo_at_once_all_get_their_notes` (four leases, three commits each,
  pushed at one barrier); end to end, scenario 14: eight agents, six pushes each, while a
  person pushes notes on the same ref with plain git (its first before any agent pushes, so
  the daemon's first notes push always meets a moved ref and merges: asserted from the
  daemon's log); every note and every one of the person's lines on Forgejo, each lease's
  notes counted once, the mirror's notes ref Forgejo's.*
- [x] A notes ref moved upstream meanwhile is merged and pushed again; a remote that refuses
