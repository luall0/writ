# History

What was built, in the order it was built: one page each, with what was planned, what was
done, the decisions and the numbers.

The milestones M0 to M10 of the [roadmap](../roadmap.md) (with M2.5, M2.6, M3.5, M3.6, M4.5, M4.6, M7.5) come first: when one is done, its
section moves from the roadmap to a page here (`m<N>-<slug>.md`), its checklist ticked with a
note under each item saying how it was verified, and a row is added below. After v1, work
starts in the [backlog](../backlog/README.md) and its pages move here when done, ending with a
"What was done" section.

| # | Item | What it brought |
|---|---|---|
| 1 | [M0 — Protocol spike](m0-protocol-spike.md) | Go for the stack: certificate-only SSH gateway (TCP and Unix socket), git fetch/push checked by the daemon in git's quarantine, daemon-signed commits through `writ-sign`, agent-held approval keys; local mode's signer chosen (CryptoKit Secure Enclave key under a `_writd` user) |
| 2 | [M1 — Lease model and policy core](m1-lease-model-and-policy-core.md) | `writ-core`: the lease model and every policy decision as pure functions, canonical ticket bytes pinned by fixtures, property-tested narrowing and template fit; `writ-store`: SQLite leases and ledger with atomic counters, append-only JSONL audit log |
| 3 | [M2 — Ticket flow](m2-ticket-flow.md) | The platform traits (portable implementations, fakes, contract suites); the approval service; the approval API over SSH and HTTPS, each optional (Q29); `writ request`, `wait`, `ls`, `sign` (trusted display, narrowing), `refuse`, `revoke`; certificates issued on approval, revocation dropping open sessions; signed or open refusals; Telegram notifications |
| 4 | [M2.5 — Code quality checkup](m2.5-code-quality-checkup.md) | The review after M2 and its fixes (pre-receive input limit, audit before change, gateway denials logged, `writ-sign` never a plain `ssh`, repo scope on fetch); one module per interface and per concern; typed errors, `tracing`, test kits; [code conventions](../conventions.md); hardened tests (no sleeps, exact codes, both sides of limits, seeded proptest); `crates/writ-integration` |
| 5 | [M2.6 — Security checkup](m2.6-security-checkup.md) | The security review after M2.5 and its fixes (no daemon exit on accept errors, revocation re-checked at push and kept across restarts and log failures, reader keys for the approval API, `allow` lists and bounds on every listener, authority files checked, a bounded trusted display, Unicode from categories, hardened YAML, explicit SSH and key types); [security conventions](../security.md); `make ci` with `cargo deny`, CI and a pre-push hook; the guarantee registry; tests that assert exact errors |
| 6 | [M3 — Signed commits](m3-signed-commits.md) | Commits signed by the daemon through the `Signer` (`writ-signer`: trait, software backend, contract suite) only as the policy allows: commits only, in their repo's `object_format`, the committer, the `Writ:` trailer found as git finds it, the paths touched (computed from objects `writ-sign` sends, each checked by its id: `writ-git`), counts and rate; the ledger holds the commit as git writes it with its signature; `on_violation: revoke_lease`; `writ init` in wrapper mode (`writ git`, the operator's git untouched) or `--whole-repo`; the operator guide; the review after M3 (a bounded walk, merges against their first parent, the lease checked before a request is read, bounded audit lines) |
| 7 | [M3.5 — Signing outside the lock](m3.5-signing-outside-the-lock.md) | `Service::sign` in three phases, so a slow or hung device never holds up approvals or revocations: the slot taken first and never given back, the signature made without the lock, the lease checked again (revoked, expired, amended, barred) before it leaves; a lease's last signature in flight not refused as used up; the `QueuedSigner` (one worker per backend use, `Busy`, `Timeout`, keys from a cache) and its contract section; a property test over interleavings of the phases |
| 8 | [M3.6 — Review after M3.5](m3.6-review-after-m3.5.md) | The security and code quality review after M3.5 and its fixes: sign request bodies within 60 s and 16 held at once, the rate window's old operations pruned, the reader key's copies wiped (and what rustls keeps written down), submission rates per source and for all sources set by the operator with every refusal counted in the log, a panicking signer backend logged once and never called again, one constructor for denials; what it found for M4 and M6 added to their sections |
| 9 | [M4 — Gateway push and fetch](m4-gateway-push-and-fetch.md) | `writ-mirror`: one hardened git builder, one reftable mirror per repo synced from upstream as untrusted input (pinned host keys, bytes and time capped, `fsck` at error level, all or none), upstream over OpenSSH with the credential in the `Signer` behind a one-operation agent socket; fetches through `decide_fetch` and the rate; every push check on what git verified in the quarantine (the ledger, the touched paths computed again, case twins), then `--atomic --force-with-lease` upstream before the mirror moves, the remote's refusals relayed; `writ init` rewrites `origin`; a lease's connections coalesced; revocation measured in flight; `make e2e` against Forgejo in Docker |
| 10 | [M4.1 — Real end-to-end scenarios](m4.1-real-end-to-end-scenarios.md) | `make e2e`: the real binaries in their own containers against a real Forgejo, the operator setup with the operator guide's own commands, twelve scenarios (ticket lifecycle, narrowing, wrapper and whole-repo modes, every push denial, upstream moved, the remote's protection, verified commits, revocation and expiry in flight, restart, a broken or hostile upstream, eight agents and a contributor at once), in CI; every command and flag of the binaries in a scenario (rule 18, a checked registry), the guides' commands checked against the pipeline's; `writd signing-keys`, `writ prove-key` (a proof is an approval); a bare config name fixed |
| 11 | [M4.5 — HTTPS upstream](m4.5-https-upstream.md) | An `https://` upstream with a token: `writd upstream-credential` (git's helper) fed by a one-operation credential socket answering only the registry's host, a one-operation SOCKS5 proxy on a Unix socket reaching only that host and capping what upstream sends, the certificate verified against `mirrors.ca_certs` or the system's CAs, no redirect, no transport for any git but its operation's own; tokens in the development keystore until M5; an HTTPS test remote in the integration tests, Forgejo behind a TLS front end to end |
| 12 | [M4.6 — Review after M4.5](m4.6-review-after-m4.5.md) | The security and code quality review after M4, M4.1 and M4.5 and its fixes: a push's mirror released at receive-pack's exit, at once on a refusal, 10 s after an acceptance at the latest (a client that stops reading holds nothing), `Mirrors::lock` with a deadline; `mirrors.ca_certs` the only trust (the system's CA directory too: reproduced on Debian, an end-to-end scenario); GnuTLS's certificate refusal read; the ledger read before a push's objects are walked; `mirrors.git`; one `MirrorError` per cause, the arithmetic lint in `writ-mirror` and `writ-gateway`, `mirror.rs` split by concern; a review loop of three passes |
| 13 | [M4.7 — Ticket link in git notes](m4.7-ticket-link-in-git-notes.md) | `ticket_link: notes`: the ledger records each pushed commit's note as waiting, with the credential that pushed it; a notes job under the mirror lock writes a notes commit, merges it into the repo's `notes_ref` (`refs/notes/commits` by default, which Forgejo and Gitea show; or `refs/notes/writ`) with `cat_sort_uniq`, pushes it as a fast-forward (moved: fetched, merged, one retry; refused: logged, written with the next push or sync); a reconcile after each mirror sync writes notes never recorded, older commits' too (a backfill); unsigned, the commits untouched; the `notes` audit event; heavy concurrency end to end with a person writing notes on the same ref |
