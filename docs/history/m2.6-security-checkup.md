# M2.6 — Security checkup

A stop between M2.5 and M3, asked for by the user: a security review of everything built so
far, the fixes the user approved, and the security conventions every later change follows
([security.md](../security.md)). No new feature beyond what the fixes needed (reader keys,
source allowlists).

- **The review**: four reviews in parallel, one per trust boundary (`writ-core` +
  `writ-proto`; `writ-approval` + `writ-store` + `writd`; `writ-gateway` + `writ-crypto`;
  `writ-cli` + `writ-sign` + `writ-platform`), each finding backed by a file and line and an
  attack, then checked again against the code; the supply chain, the build and git history
  reviewed alongside. 37 findings: one high (one accept error stopped the daemon), eight
  medium, the rest low or hardening. No critical finding: nothing let an agent get a lease, a
  signature or a push outside an approver-signed ticket that fits a template.
- **Decided with the user**: reads of the approval API need a registered reader key (SSH
  auth key, mutual TLS on HTTPS); reductions of privilege never wait for the audit log;
  submission is bounded by caps and a **required** `allow` list on the agents' TCP
  listeners; CI is `make ci` on GitHub Actions (Linux) and a `pre-push` hook (Mac); every
  finding fixed now; the shared `sessions/current` pointer waits for M6/M7; no
  `panic = "abort"` (any future panic would become a remote kill switch).
- **Added after the fixes, at the user's request**: an audit of M2.6's own changes, without
  agents (below).

**Status:** done on 2026-11-01, in nine commits (one per step) and the audit's fixes.

## What was done

**Step 1, availability and revocation** (`fix:`): a transient accept error (EMFILE, a reset)
is retried inside the transport instead of stopping the daemon; the pre-receive decision
re-authorizes the lease, so a lease revoked while its pack comes in moves no ref; session
watches are rebuilt at startup and an amendment keeps the whole subject; reductions of
privilege are applied even when the audit log can't be written (the line is kept and
written later), grants stay audit-first; unknown ids are logged; the deny list is checked in
every lease decision.

**Step 2, listener bounds and authenticated reads** (`feat:`): the `readers` file and `writ
reader` (Ed25519 client keys; mutual TLS on HTTPS); `allow` lists (required on the agents'
TCP listeners); connection, authentication, channel and body bounds; denials before
authentication coalesced; 2 pending tickets per session key, 10 submissions a minute per
address, a 5-minute minimum ttl, a bounded notification queue, `ls --all` capped; the session
checked before any state is revealed.

**Step 3, authority files and the display**: `writd.yaml`, the policy, `approvers` and
`readers` read as authority files (no link, regular, owner, not writable by others); the
trusted display bounded and ending on the enforced terms; expected paths under the scope;
quoted lists; `--yes` needs an id; one-line titles and plan steps, a 100-line task.

**Step 4, core hardening**: protected refs matched ignoring case (APFS); the hidden-character
table generated from Unicode categories; ASCII committer emails; hardened YAML options (no
anchors, aliases, merge keys, includes or interpolation); normalized, bounded caller
constraints compared byte for byte; the feedback limit in core; upstream URLs without
passwords or option-like hosts; who signed a refusal recorded, unsigned feedback labeled.

**Step 5, crypto and SSH**: `sk-` approvals need user presence; certificates with critical
options refused; approver and session key types by policy; the gateway's SSH algorithms
explicit, no compression; a poisoned session table fails closed; `receive-pack` with
`fsckObjects` and a size cap.

**Step 6, files, logs and clients**: secrets read with `read_secret`; the database and the
audit log `0600`; hidden characters escaped in the audit log, no glued lines; notifications
without agent text, Telegram `http` only on loopback; `ssh-keygen -U` by absolute path with a
clean environment (tested: never a private key file); every outside string escaped by `writ`;
private client files; no time fallback in certificates.

**Step 7, supply chain and build** (`build:`): `make ci`, the GitHub Actions workflow without
third-party actions, `make hooks`; `cargo-deny`; the toolchain pinned; `--locked`
everywhere; overflow checks in release; the shipped binaries built on their own and checked
free of test-only features; the `dev-keystore` feature; clippy denying indexing, slicing,
truncating casts and, in the parsing crates, unchecked arithmetic.

**Step 8, tests** (`test:`): the guarantee registry in the threat model, checked by
`tool/check-guarantees.py`, with three new guarantees; about 80 assertions that accepted any
error now assert the exact one; `tool/check-rules.py` refuses bare `is_err()`/`!success()`,
unmarked sleeps in tests, lock-skipping, relative program paths and unexplained `#[allow]`s;
`RefusalCode` on service refusals.

**Step 9, docs** (`docs:`): [security.md](../security.md); AGENTS.md rule 17 and the
definition of done; the threat model's new residual risks and boundary 5b; this page.

## The audit of M2.6's own changes

Run after step 8, without agents, over `a9b503d..HEAD`, reading every changed file against the
new conventions. Found and fixed in the same commit as this page:

- **Per-source bounds bypassed by rotating IPv6 addresses** (medium): a host with a /64 was
  2^64 sources for the connection slots, the submission rate and the denial coalescing. An
  IPv6 source now counts as its /64, and denials before authentication have a global budget
  (60 lines a minute).
- **Authority files owned by root were refused** (low): that is how a container mounts its
  configuration (M8), and as safe; accepted for authority files, never for secrets.
- **The mutual-TLS requirement rested on a rustls default**: now stated in the verifier.
- **Residual, documented**: without an `allow` list on the approval listener, its connection
  slots can be held by strangers (a denial of service, nothing granted or read); local mode
  shares one submission rate. Both in the threat model, with their mitigations.

A second round, the same way, over the result:

- **A refused TLS handshake left no audit line** (medium, hard rule 9): a stranger's client
  certificate on the HTTPS approval API was dropped silently. Now a coalesced `connect`
  denial with the reason, tested.
- **A plain key for a user other than `writ` on the agents' listener was refused silently**:
  now a coalesced line naming the user (cut to 64 characters).
- **Peer-caused diagnostics were warnings** (a connection failing, a caller the attestor
  turned away, an HTTPS error): any peer could grow the daemon's stderr without bound. Now
  `debug`; an audit-log outage is reported once, not per kept line.

A third round found one gap in the checks themselves: `tool/check-rules.py` treats what
follows a file's `#[cfg(test)]` module as test code, so production code placed after it
would have escaped the rules. The script now refuses code after the test module. Every
fallback the milestone added was checked to fall toward deny.

A fourth round checked the new conventions against the configuration: a key listed both as
an approver and as a reader would open the API and sign approvals alike. The daemon now
refuses to start with one (tested).

A final tour, without agents, read every production file of every crate along the trust
boundaries (not only M2.6's changes). Nothing let an agent get a lease, a signature or a push
outside an approver-signed ticket. Found and fixed:

- **One accept error ended the hook server** (medium): the gateway's pre-receive socket
  stopped on any accept error, EMFILE included, and every later push was refused until a
  restart (the bug class of step 1). It now accepts through `accept_retrying`, made public in
  `writ-platform` for every listener (tested with scripted errors).
- **The guarantee registry ahead of the daemon** (docs): the signing and push guarantees are
  enforced by the policy core, which the gateway calls from M3 (signing) and M4 (pushes); the
  threat model now says so above the registry.
- **The Telegram token and the environment's proxy** (low): ureq's default reads
  `ALL_PROXY`/`HTTPS_PROXY`/`HTTP_PROXY`, so with an `http` loopback base the token could
  reach a proxy in clear. `proxy(None)`, tested in a child process with every proxy variable
  set.
- **Peer-caused warnings** (low): transient accept errors and a client hanging up mid-fetch
  were `warn` lines any peer could repeat; now `debug`, with one warning per accept when a
  shortage lasts (tested on both sides of the bound).
- **Repo names equal ignoring case** (low): two registry entries `Demo` and `demo` would share
  one mirror on APFS; the policy now refuses them.

Noted, not a security issue: an amendment that extends `expires_at` keeps the certificate's
first `valid_before`, so the extension stops at the old expiry (fails closed; for M6, where
amendments become an agent workflow).

Checked and found sound: the reader verifier (SPKI comparison, handshake signature, TLS 1.3
only); the order of `bar_serial` and the announce, and every lock taken by the startup
re-watch (no deadlock, no lost revocation); the audit retry queue (bounded, ordered, grants
still refused while the log is down); the source check before any SSH byte is parsed; the
coalescing reasons (no secret, bounded text); the new file helpers (`O_NOFOLLOW`,
`O_NONBLOCK`, checks on the opened file); the display bounds and the enforced summary; the CI
workflow (read-only token, no third-party code).

## Kept as they are, with the reason

- `panic = "abort"`: refused; with the lints, a panic is a bug, and abort would make any one a
  remote kill switch.
- The shared `~/.writ/sessions/current` pointer: one per host until M6/M7, where it becomes a
  per-repo session path (two agents on one host would otherwise switch each other's lease).
- The watcher contract's 300 ms quiet check: not a sleep-then-assert; no callback is the only
  correct outcome, and the bound only stops looking.
- Two unmaintained advisories under `age` (`proc-macro-error2`, `basic-toml`): compile time
  only, no upgrade without leaving `age`; listed in `deny.toml` with their reasons.

## The security checklist, for M2.6

1. **Inputs**: new ones (reader keys and client certificates, `allow` lists, the `readers`
   file) are in the inventory with their bounds and hostile tests.
2. **Authority**: reads now need a reader key; grants unchanged (signed).
3. **Fail closed**: the fallbacks found were turned toward deny; poisoned locks fail or
   recover; accept loops never end on a connection's error.
4. **Audit**: grants first, reductions never blocked, unknown ids logged, floods coalesced.
5. **Revocation**: re-checked in the hook; watches rebuilt at startup; pushes forgotten.
6. **Secrets**: read with `read_secret`; no agent text or token leaves for a third party.
7. **Display**: bounded, ends on the enforced terms; outside text escaped everywhere.
8. **Dependencies**: `rustix` and `rustls-webpki` (both already in the tree), `cargo-deny`
   policy; `serde-saphyr` and `russh` reduced to the features used.
9. **Guarantees**: the registry, with three new guarantees and their tests.
10. **Threat model**: boundary 5b (files that grant authority), new residual risks; nothing
    weakened.
