# M7.9.7 — Fetch without a signature

Asked by the user before M8, from agents seen at work: before planning, an agent fetched
with plain `git`, outside the skill and through the operator's own remote, because a fetch
needed a lease and a lease a signed ticket. Now a template's `unsigned_fetch: <duration>`
lets a new ticket that only fetches be granted when it is submitted, with no approver, for
at most that time; every other ticket under the same template is signed as before. `writ git
fetch` and `writ git pull` with no lease ask for one themselves and close it when git
returns, and both skills fetch before they plan. The forks settled with the user are in the
[decision log](../decisions.md) (2026-11-15, M7.9.7, and the row that reworked it).

**Status:** done (2026-11-15). `make ci` passes on macOS (1228 tests) and `make e2e`
passes (41 scenarios). The user ran the manual check on their Mac after the last fix
(`7d7ec33`): an agent under `writ run` fetched before writing its ticket, with no prompt.

**Found while building it:**

- **Reworked with the user once built** (`0501cd9`): the first design made `unsigned_fetch:
  true` a kind of template that could only fetch, one per repository, never mixed with a
  signed one. What the user wanted was the fetch unsigned while the template still signs and
  pushes. `unsigned_fetch` is now a duration on any template that allows `fetch`; the short
  form (`251e56b`), the guided `repo add` question and the "one per repository" rule went
  with it.
- **A fetch-only template with `max_push_size: 0` refused every fetch** as "no longer
  configured" (step 3): the bound is a push's only, and the gateway now checks it only for a
  push.
- **`require_expected_paths` refused the fetch `writ git` asks** (found by the user on the
  real install, `7d7ec33`): the ticket `writ` writes lists no paths. The requirement now
  applies to a repo block that asks `commit_sign`: paths are compared on the commits a block
  signs, and a block that only fetches or pushes has nothing to list.
- **Found while closing, three acceptance claims without a test**, added (`03cdead`),
  each failing when the check it covers is removed:
  `unsigned_leases_count_against_the_submission_rate_not_the_active_leases` (the per-source
  rate refuses an unsigned ticket one past it and a second before its window ends, takes one
  at its end; four unsigned leases held under `max_active_per_source: 1`, a signed one
  still granted, a second refused); `writ_git_fetch_with_no_lease_asks_none_when_no_template_has_the_switch`
  (git run as before, refused for want of a session key, nothing submitted, `pull` too);
  `writ_git_fetch_under_a_running_lease_without_fetch_is_refused_never_replaced` (the fetch
  refused under the running lease with code `operation`, no other lease asked, `pull` too).
- **A full queue of waiting tickets also refuses an unsigned fetch**: `max_pending` is
  checked at admission, before the grant, so an unsigned ticket is refused (`TooManyPending`)
  while `max_pending` tickets wait for the approver. Fail-closed, and
  bounded by what the approver lets wait; recorded here, not changed.

## What was planned

[The roadmap's M7.9.7](../roadmap.md) as it stood:

Asked by the user before M8, from agents seen at work: before planning, an agent fetches to
see whether upstream moved or to start from a clean tree, and it does so with plain `git`,
outside the skill, because `writ git fetch` needs a lease and a lease needs a signed ticket.
In wrapper mode plain `git fetch origin` goes through the operator's own remote and
credentials. On a large repository the first fetch is needed almost every time, so the agent
would ask a lease only to plan the real one. A fetch sends nothing upstream and can't write,
and what it reads is the repository's ([scope](../threat-model.md#looked-at-and-not-risks)): a
fetch-only lease needs no approver. Settled with the user
([decision log](../decisions.md), 2026-11-15):

- **A template's switch, not a kind of template** (reworked with the user once built: the
  same template signs and pushes as before): `unsigned_fetch: <duration>` on any template that
  allows `fetch` (from the daemon's `min_ttl` to 1 h; absent: off, the default). A new
  ticket (amending and renewing nothing) whose every repository asks only `fetch`, each
  under a template with it on, is granted with no signature, for at most the smallest
  `unsigned_fetch`; every other ticket under the same templates is signed as before, and one
  the approver narrows down to fetch only is signed by them. It is set like any template
  field (`writ admin template set|edit`, asked after `max_ttl`, a signed admin change), and
  applies to every repo naming the template (one repo alone gets a template of its own). The
  signed policy change is the approval that stands for the missing SSHSIG.
- **The grant:** granted when it is submitted, with no pending state and no notification, its
  certificate issued as any lease's; never amended or renewed (refused with its code). Its
  time is checked at submission, at the grant and on every request: a switch turned off, or
  shortened below it, ends it. Unsigned leases count against the submission rates
  (`submissions` in `writd.yaml`) like any ticket, not against `max_active_per_source`. The
  state records how each lease was granted (signed by an approver, or by the policy), as a
  state step (version 13). The grant's audit line names the template where a signed one
  names the approver; `writ ls`, `writ report` and the approver's screen mark an unsigned
  lease as such.
- **Transparent for the agent:** `writ git fetch` and `writ git pull` with no lease named
  (`WRIT_SESSION` unset, no active `current`) ask for one themselves: they read from
  `writ policy` the first of the repository's templates with `unsigned_fetch`, make a throwaway
  Ed25519 key file, submit a fetch-only ticket written by `writ` (that template, its
  `unsigned_fetch` time, the title and task fixed), run git under it, close it
  and remove the session's files, whatever git's exit. A close of an unsigned lease records no
  run in the timings file. No such template: the denial a fetch without a lease has today,
  with its reason. A lease named but ended, or one without `fetch`, is refused as today:
  `writ git` never switches a running agent to another identity. A `pull` that would make a
  merge commit fails at its signature (no `commit_sign`): the skill says `--ff-only`.
- **Always a file key:** a lease granted with no signature has a file session key, whatever
  the host's `session_key` setting or the template's ([M8.5](../roadmap.md#m85--non-exportable-session-keys)
  refuses a ticket for one that declares `hardware`; the template's mode is for the leases
  the approver signs). A hardware key guards what an approver granted; anyone who may submit
  from an allowed address gets the same fetch lease with no key to copy.
- **The skills and the pointer line:** both skills gain a step before the ticket, "fetch
  before you plan" (`writ git fetch origin`, `writ git pull --ff-only`; the work itself still
  under a ticket the human signs), `writ policy` showing it as `fetch alone: no signature`,
  and the line
  `--agents-md` writes in `AGENTS.md` / `CLAUDE.md` names fetch and pull. `writ init` writes
  them again in each wired repository.
- Docs: the [lease model](../lease-model.md) (the key, the grant, the lifecycle without
  `pending`), [flows](../flows.md) § 4, [approvals](../architecture/approvals.md) (a grant with no
  approval), [identity](../architecture/identity.md) and [clients](../architecture/clients.md)
  (`writ git` with no lease), [policy and state](../architecture/policy-and-state.md) (the
  record, the audit line), the operator reference and the policy template (`unsigned_fetch`), the
  [threat model](../threat-model.md): a row in "looked at, and not risks" (a fetch-only lease
  granted without a signature: it sends nothing and can't write, and what it reads is the
  repository's; a risk if a fetch ever sent upstream something of the agent's, or if such a
  lease could widen into one that signs or pushes), the guarantee that it only fetches, and
  the sentences that say every lease was signed (boundary 4, the residual risks on leases
  shared on one host and on submissions) made true of every lease that signs or pushes.

## Left open

- **A fetch with no lease where nothing allows one is refused by ssh, not by Writ**: git runs
  as before and ssh says `Identity file …/sessions/current/key not accessible` and
  `Permission denied (publickey)`. As before M7.9.7, and what the plan asked; a reason in
  Writ's words (no lease, no template with `unsigned_fetch`) would be clearer to an agent.

## Security checklist

1. **Inputs:** the switch is a key of the signed policy, read strictly with its bounds (from
   `min_ttl` to 1 h, only on a template that allows `fetch`), each bound tested on both
   sides; the ticket is read as before; the store's `unsigned` column decoded strictly, a row
   whose flag and approval disagree corrupt. No new untrusted input.
2. **Authority:** the one lease granted with no signature fetches only, by its own terms,
   never widened (an amendment, a renewal and an approval of it refused); the approval that
   stands for it is the signed policy change that set the switch. Checked at submission,
   again before it is recorded (in phases, the certificate signed outside the lock), and on
   every request against the policy in force. Every other ticket, under the same template,
   is signed as before.
3. **Fail closed:** the switch off or shortened ends the lease (`config`); a policy changed
   between the decision and the record discards the certificate; `writ git` never replaces a
   lease named or running, and with no template it runs git as before, refused.
4. **Audit:** the `submit` and `grant` lines (the template named, no approver), every fetch,
   refusal and close as for any lease; `writ ls`, `writ report` and the approver's screen
   mark it `no signature (unsigned_fetch)`.
5. **Revocation:** as any lease; it also ends with its template's switch.
6. **Secrets:** `writ git`'s throwaway session key and certificate written `0600` like any
   session's and removed when git returns, on its failure too; always a file key, M8.5's
   hardware key refused for it. Nothing secret printed.
7. **Display:** the daemon's reasons and states cleaned before they are shown; the skills and
   the pointer line are client text, steering an agent, never a check.
8. **Dependencies:** none added.
9. **Guarantees:** one added (a lease granted with no signature only fetches), with its tests
   in the threat model; the rates and `writ git`'s two refusals tested when closing.
10. **Threat model:** boundary 4 and the residual risks' sentences on signed leases made true
    of every lease that signs or pushes; a row in "looked at, and not risks" (a fetch-only
    lease granted without a signature).
