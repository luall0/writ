# M6.1 — Multi-repo workspaces

One agent at the root of a folder of repositories, which works on all of them
([Clients § Workspaces](../architecture/clients.md#workspaces),
[a folder of repositories](../operators/clients.md#a-folder-of-repositories)). Split off M6
when M6 was replanned with the user (the decision log's 2026-11-04 rows).

**Status:** done (2026-11-04). `make ci` and `make e2e` passed, run by the user (the
integration tests on macOS, after one fix to the test itself, below). Per-repository tickets,
asked for by the user while it was built, are planned as
[M6.1.5](../roadmap.md#m615--per-repository-tickets).

## What was planned

- **`writ init` at a workspace root**: the child repositories one level down are found (the
  root itself may be a repository too, a meta-repo with its children ignored); each is mapped
  to its registry name (by default its `origin` URL's last part, else its folder's name,
  confirmed on a terminal; `--repo <dir>=<name>`, repeatable, answers for it) and wired; the
  workspace is recorded so `writ init --undo` at the root takes every repository back.
- **The `writ-workspace` skill**, installed at the root instead of `writ`: one ticket naming
  every repository the task touches, `writ git -C <repo> …` for each command, the trailer per
  repository, timings per repository.
- **`writ git` reads git's global options as git does**, in order (`-C`, `-c`,
  `--git-dir`, `--work-tree`, `--no-pager`, `-p`, `-P`, `--namespace`, `--bare`…), to find the
  repository a command works in; what it can't resolve is refused. At an unwired root it
  lists the workspace's repositories.
- **`writ exec -C <dir> -- …`**: one repository per process. A program that runs git across
  several repositories at once stays in the [backlog](../backlog/README.md), and so do
  submodules.

## What was done

**A workspace** (`writ_cli::workspace`, `writ_cli::init`)

- `writ init` with no repo named makes the folder a workspace. Its repositories are the
  folders right under it that are a repository's top (`git rev-parse --show-toplevel`),
  sorted, at most 256. Hidden folders and plain folders are not; links, names that aren't
  UTF-8 or hold a control character, and submodules of the folder's own repository are left
  aside and named in the summary.
- Registry names: `--repo <dir>=<name>` (`<dir>=-` leaves one out: `-` is never a registry
  name; a trailing `/` is taken), else asked on a terminal with the default (origin's last
  part without `.git`, else the folder's name). Without a terminal, any repository nobody
  named is refused, each listed with its default, before anything is written; so are a
  `--repo` folder that isn't one of them, a folder named twice, two repositories under one
  name, a repository already wired and a folder already a workspace. The folder's own
  repository is a member only when named (`--repo .=<name>`).
- Each repository is wired by the same code as `writ init <repo>` (`init::wire`, the same
  `wiring::settings`, its own `<git common dir>/writ/config`, either mode, `--email` and
  `--lease` for all), with `writ.workspace` naming the folder and no skill of its own.
- The record, `<folder>/.writ-workspace` (git config format): `writ.mode`, `writ.lease`,
  `member.<dir>.repo` (each written before its repository is wired, so a run stopped half way
  is taken back), and the skill's entries. When the folder is a repository, `/.writ-workspace`
  and the skill's folder go in its `.git/info/exclude`.
- `writ init --undo` at the folder takes back each repository whose own record names this
  folder (one that doesn't is named and left), then the skill, the exclude and pointer lines
  and the record. In one of its repositories, `--undo` refuses and names the folder.
- The record is read bounded (a regular file, never a link, 64 KiB, 256 repositories, each a
  plain folder name or `.`); a hostile one is refused whole.

**The skill** (`skill/writ-workspace/SKILL.md`, `writ_cli::skill`)

- Built into `writ` beside the `writ` skill, installed at the folder in the agents' folders
  (`writ-workspace/`), listing the repositories with their registry names: one ticket naming
  every repository, `writ policy <repo>` for each (the trailer is per repository; a ticket
  for several fits one template allowing them all, until M6.1.5), `writ git -C <dir>` for
  every git command, `writ exec -C <dir>` for a program, `writ mark` and `writ close` at the
  folder, the timings per set of repositories. `--agents-md` adds its own pointer line.
- Every undo (a repository's too) now removes only a `SKILL.md` in a `writ/` or
  `writ-workspace/` folder that still carries Writ's mark, and the folders `writ init` made
  for it once empty (`skill.createddir`); the pointer line only from `AGENTS.md` or
  `CLAUDE.md`.

**`writ git` and `writ exec`** (`writ_cli::gitopts`, `writ_cli::wrap`)

- git's global options read in git's order and forms (`-C`, `-c`, `--config-env`,
  `--git-dir`, `--work-tree`, `--namespace`, `--super-prefix`, `--attr-source`,
  `--shallow-file`, `--exec-path=`, `-p`, `-P`, `--paginate`, `--no-pager`, `--bare`, the
  pathspec, replace, lazy-fetch, optional-lock and advice flags), only to find where the
  command starts; then git itself resolves the repository from `-C`, `--git-dir`,
  `--work-tree` and `--bare` (`git … rev-parse --git-common-dir`, in the command's
  environment, so `GIT_DIR` counts as it will). An option git doesn't take before a command,
  a missing value or an option that isn't UTF-8 is refused with its reason, git never run.
  `--version`, `--help`, `--exec-path` alone and `--list-cmds` run git with no wiring.
- `writ exec -C <dir>` runs the program in `<dir>` under its repository's wiring.
- At a workspace root that isn't a wired repository, `writ git`, `writ exec` and `writ
  policy` (no repo named) list the repositories.

**Timings and marks** (`writ_cli::close`)

- `writ close` at the folder (or in one of its repositories) records the run in the
  workspace's timings file, in the section named by the lease's repositories, sorted and
  joined with ` + ` (`api + web`). `writ mark` uses the workspace's pinned lease.

**Registries**

- The end-to-end registry test now counts a flag with only a short name (`writ exec -C`);
  rows for `writ init --repo` and `writ exec -C`.

**Fixed while it was tested**

- The integration test compared the folder's path as it built it (`/var/folders/…`) with the
  one `writ` recorded (`/private/var/folders/…`): on macOS the temporary directory is reached
  through a link. The test now resolves the folder once (commit `448b360`); `writ` was right.

## Decisions

In the [decision log](../decisions.md), 2026-11-04: a workspace is `writ init` with no repo
named, recorded in `<folder>/.writ-workspace`; registry names given or confirmed, never
guessed, the folder's own repository only when named; `writ git` reading git's global options
and letting git resolve the repository; a workspace run's timings section named by the
lease's repositories, and an undo removing only what is still Writ's. M6.1.5 (per-repository
tickets) added after it at the user's request.

## The security checklist, for M6.1

1. **Inputs:** `writ git`'s arguments (parsed as git parses them, refusals tested), the
   workspace record, `--repo` answers and the records' `skill.*` entries (64 KiB, no link,
   256 repositories, plain folder names; hostile records refused whole): client-side, in the
   inventory with their bounds and hostile-input tests.
2. **Authority:** none added; everything here is a client-side convenience, the daemon checks
   every request.
3. **Fail closed:** unknown git options, unnamed repositories without a terminal, hostile
   records and repositories not wired from this folder are refused or left, never guessed.
4. **Audit:** not touched (no daemon change).
5. **Revocation:** not touched.
6. **Secrets:** not touched (no key material in the records or the skill).
7. **Display:** every folder name, record value and git message shown escaped; the listings
   are Writ's own lines.
8. **Dependencies:** none added.
9. **Guarantees:** none changed; `writ-sign` still refuses a commit made outside the wired
   repository.
10. **Threat model:** the skill row extended to the wiring and workspace records and what an
    undo touches; no new residual risk.
