# M7.5 — Secure Enclave signer on the Mac

Non-exportable keys in local mode: `se-cryptokit`, a CryptoKit Secure Enclave key per key,
made by the device through `writ-se` (a stateless Swift helper process), its framed blob sealed
in the keystore; agent signing keys, `ssh` upstream credentials and the HTTPS approval API's
TLS key can live there. The TLS key is moved or rotated live by a signed admin change (`writ
admin tls rotate`); every key's backend is chosen from the CLI; the installer is guided
([signer](../architecture/signer.md#a-helper-process),
[macOS Secure Enclave](../architecture/macos-secure-enclave.md),
[approvals](../architecture/approvals.md#writ-admin-tls-rotate),
[conventions](../conventions.md#installers-are-guided)). The forks settled with the user at its
start, and those settled while building, are in the [decision log](../decisions.md)
(2026-11-12, M7.5).

**Status:** done (2026-11-12). `make ci` passes on macOS (980 tests), with the Secure Enclave
scenarios on this Mac's real Secure Enclave; `make e2e` passes (36 scenarios: 16 rotating the
TLS key and making a keystore with `--tls-backend`, 23 moving keys with `--backend`). The
real-install items
(the daemon under `_writd`, a reboot, the screen locked) run with M7.9's real install, where
the user moved them.

**Found while building it:** corrupted CryptoKit blobs sent to the real Secure Enclave made its
firmware panic (`SEP Panic: :sks`) and crashed the Mac. CryptoKit's own `try!` aborting the
process (M0's finding) was not the worst case. Since then, no blob reaches the device unless
it is the one the device made for that key (a frame with a digest, checked first), and hostile
input for hardware goes to the fake helper only ([testing](../testing.md#hardened-tests)).

## What was planned

The [roadmap's M7.5](../roadmap.md) as it stood when the milestone closed: `create_key` beside
`add_key`; a router over several backends per use; a helper process (`writ-se/1`), generic in
Rust and tested against a fake; the blob sealed in the keystore, a refused one leaving its key
listed and unusable; agent keys and upstream credentials on `se-cryptokit`; every key's
backend from the CLI (asked by the user); the TLS key moved by a signed admin change, live
(settled with the user); the installer guided (asked by the user while building it).

## What was done

1. **The interface** (`writ-signer`): `Signer::create_key` → `Created { info, stored }`
   (`Stored`: wiped, its `Debug` its length), `MakesNoKeys`, `Capabilities::makes_keys`; the
   queue carrying it; `route::Routed` over named backends; `create_key_contract`, run by
   `testing::FakeDevice`.
2. **The helper signer** (`writ_signer::helper`): `writ-se/1` over a helper's stdin and
   stdout, every answer checked (each signature verified, points on the curve), a helper that
   dies, lies or stays silent killed and the next job served; `writ-fake-se` with every fault.
3. **`writ-se`** (Swift, `writ-platform-macos/swift/`), built by `build.rs` and
   `tool/build-writ-se.sh`; the framed blob (`writ-se-blob/1`, SHA-256 over the key's point and
   the blob) checked before any helper sees it; the contract on the real Secure Enclave.
4. **`writd`:** `BACKENDS` per OS; keys made through `Makers` (by the device for a device
   key); the key file naming its backend (`writ-key/1`, the blob in hex); each use's signer a
   router; `signers.se_cryptokit.helper`; a blob refused at unseal → the key unusable, one
   `admin` line, the agent denied naming `writ admin key rotate`.
5. **The CLI:** the daemon's backends in `writ admin key list`; `backend` asked by the guided
   `key add` and `repo add`; `writ admin key rotate --backend`; a token on a device refused.
6. **The TLS key:** `writ-tls/1`, `tls show` / `tls rotate`, `TlsIdentity::replace`, the boot
   tier rotated as `.new` files, `writ` replacing its own pin; `writd init --tls-backend`.
7. **The installer guided:** every choice asked (the setup, the approval key, on a Mac the TLS
   key's and `agent-01`'s backends), the summary of every change, nothing done before
   `Install?`; the uninstall the same; variables for scripts only.

## Security checklist

1. **Inputs:** new ones in the [inventory](../security.md#untrusted-inputs), each with its
   bounds and hostile tests: the Secure Enclave helper's answers (and the stored frames
   checked before use), a TLS key rotation (`writ-tls/1`), the daemon's new certificate in its
   reply. The key file's new layout is the daemon's own, read exactly.
2. **Authority:** keys still made only by a signed policy change; the TLS key moved only by an
   approver's `writ-tls/1` bound to the certificate in force; the CLI's checks a convenience.
3. **Fail closed:** a blob that doesn't check never reaches the device and makes its key
   unusable; a helper that lies is killed; an unknown backend, a stale rotation, a failed
   build all refuse with the reason and keep what was; the installer changes nothing before
   its go.
4. **Audit:** an `admin` line per unusable key at unseal and per rotation (done or denied).
5. **Revocation:** not touched.
6. **Secrets:** a device key's file holds its framed blob, usable only by that Mac's Secure
   Enclave; `Stored` zeroized and never printed; no private key of a device key exists.
7. **Display:** what the daemon sends (backends, fingerprints) shown escaped.
8. **Dependencies:** `p256` 0.14.0 direct in `writ-signer` (already in the tree through
   `ssh-key`, same features); `swiftc` from Xcode's command line tools on the Mac.
9. **Guarantees:** a new line (a device gets only the blobs it made; a helper's failure costs
   one job), and the hardware line's tests.
10. **Threat model:** the Secure Enclave firmware panic and a foreign blob on another Mac; the
    TLS re-pin over the old channel.
