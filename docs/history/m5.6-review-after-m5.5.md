# M5.6 — Review after M5.5

A stop between M5.5 and M6, asked for by the user: a security and code quality review of the
whole code after M5 and M5.5 (about 48,000 lines of sources, their tests, the tooling and the
docs), a report discussed in the chat, then every finding fixed but those a later milestone
takes, each with the test that would have caught it, the three test layers hardened, and the
rules of [security.md](../security.md) and [conventions.md](../conventions.md) sharpened so
the next change doesn't bring the findings back.

**Status:** fixes done and pushed (fourteen commits); waiting for the user's `make ci` and
`make e2e` runs (this container has git 2.43, the integration tests need 2.47, and the e2e
pipeline is the user's), then a second review pass, by one reviewer without agents, until a
pass finds nothing. This page is completed then, and the roadmap's section moved here.

- **The review**: seven reviewers in parallel, one per area (core, proto and store; the
  approval service; the gateway and writ-git; the mirrors; crypto, signer and keystore; writd,
  the platform crates and the clients; tests, tooling and docs), each finding checked against
  the code before it was kept, the two strongest reproduced with real git (S1, S4). One high,
  eleven mediums, about thirty lows, code quality, test and doc items.
- **Decided with the user**: upload-pack in protocol v0 with reachable wants (S4, after the
  compatibility was measured: every client falls back, `git fetch origin <sha>` of a reachable
  commit kept); a removed approver's leases revoked (L5); the author checked like the
  committer (D2); a person's note kept as written (L11); every finding fixed now but three
  moved to later milestones (SIGTERM to M7 and M8, `writd keys create` refused while the
  daemon runs to M7, a whole-repo clone following its lease to M6); the e2e layer must prove
  that protocol v0 breaks no client.
