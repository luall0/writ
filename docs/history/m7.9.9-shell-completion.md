# M7.9.9 — Shell completion

Asked by the user before M8: `writ` has some forty commands, most with a lease id or a name
from the registry to type, and none of it completed. Now `writ` completes in bash, zsh and
fish: its commands, flags, enum values and paths, and the daemon's values (the tickets
waiting, the leases running, the policy's names, the fields of `set` and `add`), read live
with the reader key within one second, silent when the daemon can't answer, with no agent
text in the menu. `writ completions <shell>` prints the registration, and `make install`
writes it for each shell that names a completion directory. The forks settled with the user
are in the [decision log](../decisions.md) (2026-11-15, shell completion), and what was
settled while building it in the row of 2026-11-16. Released as **0.3.0**.

**Status:** done (2026-11-16). `make ci` passes on macOS (1244 tests) at 0.3.0, and
`make e2e` passes (43 scenarios).

**Found while building it:**

- **clap offers a hidden command typed far enough to match it alone**: completion answers
  from a copy of the tree without the hidden commands (clap's `string` feature to rebuild it
  with owned names). Flags stay as they are: rebuilding them would break the conflicts that
  name them, and none is hidden.
- **One argument struct serves four nouns** (`EntryCommand`: repo, host, proxy, recipient):
  the values are attached by command path in the copy, not in the derive.
- **`writ wait` waits for a decision**: it offers the waiting tickets (the plan said running
  leases), `wait --lease` the running ones.
- **An empty word offers the command's flags beside its values** (clap's engine): "no value"
  in the silence tests is no daemon value, the flags still offered.
- **zsh's registration only registers when sourced**: as `_writ` on `fpath` it now also
  completes, so an installed file answers its first TAB.
- **A delay injected to test "answering just before the deadline" is a test passing by
  timing**, which the hardened-test rules refuse: the held relay (the TAB waits the full
  second, then nothing) stands beside the same relay forwarding at once (the lease offered),
  so holding is the only difference.
- **compsys runs only in an interactive zsh**: the tests run zsh's own completion function
  with `words` and `CURRENT` set and `_describe` and `compdef` stood in for.

## What was planned

The roadmap's M7.9.9 as it stood:

Asked by the user before M8, after [M7.9.8](m7.9.8-versions-and-changelog.md): `writ` has some forty commands, most with a lease id or a name
from the registry to type (`writ sign wrt_01JD8X…`, `writ admin template show agent-web`), and
none of it completes. Settled with the user ([decision log](../decisions.md), 2026-11-15):

- **`writ` only, in fish, zsh and bash.** `writd` is run by the installer and the service,
  `writ-sign` by git: neither gets completion.
- **One engine, `writ` itself:** clap_complete's dynamic engine (`CompleteEnv`, its
  `unstable-dynamic` feature, the exact version pinned, its row in [stack.md](../stack.md)). On
  each TAB the shell runs `WRIT_COMPLETE=<shell> writ -- <words>` and `writ` answers from its
  clap tree: commands, flags, enum values, paths, and the values below. The variable is named
  `WRIT_COMPLETE`, not clap's default `COMPLETE` (every variable a binary reads is `WRIT_*`),
  with its rows in the operator reference and the configuration registry (rule 19). Commands
  meant for scripts, not people (`writ prompt`), are hidden from completion as from `--help`.
- **Values read live, never cached:** each value comes from the read its command already
  makes with the reader key, no approver signature involved: ticket and lease ids from `writ ls`:
  the waiting tickets for `sign`, `refuse` and `wait` (settled while building it: `wait`
  waits for a decision), the running leases for `revoke`, `report`, `close` and
  `wait --lease`, the registry's repo, template, key,
  host, proxy and recipient names for `writ admin …` and `writ policy` (from their `list`
  reads), the fields of `writ admin … set|edit` from the list `writ` already checks them
  against. A read has a hard deadline (1 s, from the connection to the last byte); no file is
  written on the host, no state kept between two TABs.
- **Silent when the daemon can't answer:** sealed, unreachable, slow past the deadline, its
  host key or TLS certificate not pinned, the reader key missing or refused, a reply that
  doesn't parse: no value is offered, nothing is written to the terminal, the exit is the
  shell's ordinary empty answer; commands, flags and paths still complete. Completion never
  prompts, never asks for Touch ID or the approval key, never pins a host key on first use.
- **Only daemon facts in the menu:** fish and zsh show a description beside each value; a
  ticket's is its state, template and repository count (`pending · agent-web · 3 repos`),
  never its title, task or any agent-written text (rule 6). Every candidate and description
  is bounded (a count and bytes per reply) and has its hidden characters removed before it
  reaches the shell, a new untrusted input in the [security inventory](../security.md#untrusted-inputs)
  with its hostile-input test.
- **Installed for the operator:** `writ completions <fish|zsh|bash>` prints the line that
  registers the engine for that shell. `make install` writes it into each installed shell's
  system completion directory, asked of the shell itself where it can say (fish's
  `$__fish_vendor_completionsdirs`, a `site-functions` directory on zsh's `fpath`,
  bash-completion's `completionsdir`), skipping a shell not installed and printing the line
  to add by hand for one that names no directory; the files it writes are recorded, and
  `make uninstall` removes exactly those.
- Docs: [clients](../architecture/clients.md) (the engine, the values and their reads, the
  silence), the operator page for the client's settings (`writ completions`, `WRIT_COMPLETE`,
  the line for each shell), [install](../operators/install.md) (the files written and removed),
  the [security inventory](../security.md#untrusted-inputs), the end-to-end coverage registry.

- [x] With the daemon running, `writ sign <TAB>` offers exactly the waiting tickets, `writ
      revoke <TAB>` the running leases, `writ admin template show <TAB>` the templates; each

      *`when_the_daemon_can_t_answer_nothing_is_offered_nothing_said_within_the_deadline`

## Left open

- **zsh's real compsys is not in the tests** (it runs only in an interactive shell): its own
  completion function is. A TAB in your own zsh, fish and bash on the Mac is the check worth
  making by hand.
- **A TAB has no parsed flags**: `--approval-url` typed on the line isn't used for the
  values; its variable and the settings file are.

## Security checklist

1. **Inputs:** one new client-side input, the daemon's replies as completion values: bounded
   in count and bytes, plain characters only, descriptions stripped
   ([inventory](../security.md#untrusted-inputs)); hostile-input tests.
2. **Authority:** only the reads the reader key already makes (`writ ls`, the policy in
   force); nothing signed, granted or changed.
3. **Fail closed:** any failure offers no value, within the 1 s deadline.
4. **Audit:** each read is a reader's, logged as before.
5. **Revocation:** unchanged.
6. **Secrets:** the reader key read, never written or made; nothing on a TAB's stderr; no
   host key pinned.
7. **Display:** no agent text in the menu (rule 6).
8. **Dependencies:** clap_complete `=4.6.9` with `unstable-dynamic` (pinned exactly, its
   shells run in the tests), is_executable; clap's `string` feature; `cargo deny` passes.
9. **Guarantees:** none changed.
10. **Installer:** writes root-owned files of writ's own registration, takes back only its
    three shapes of paths.
